# Luma evaluation — 25 November 2026

Platform: macOS Apple Silicon. Runtime Cactus 4.0.0 revision
`1a028f5a3972b67dd8d8752f882113d475e7ec4c`; Needle revision
`c95d25b4efa1e9601e785d92438e4ade0dbddbf8`. All local inference;
no saved content or prompts were sent to a service. See the adjacent raw JSON
report and `scripts/evaluate-luma.py` for the exact prompts/schema.

## Raw model findings

- A Telugu song command and Telugu John 3:16 command were suppressed at low confidence.
- A mixed Telugu/English song request proposed an extra search for a command word.
- `show ఆదికాండము 1:1` lost the verse number and proposed a whole chapter.
- Missing-book and ambiguous-book requests were accepted without clarification.
- A simple English `genesis 1:1` reference was retained correctly.
- Raw requests completed in under one second on this Mac. This small sample is
  not a general accuracy or performance benchmark.

These findings do not establish Telugu fluency. Selah now grounds explicit
references and common Telugu song-search wrappers before invoking the model.
The app-level evaluation verifies review, exact saved verses and unchanged live
state independently of the raw model report.

## Windows status

The pinned Windows x64 runtime was downloaded and checksum verified on the Mac.
That checks availability/integrity only. It was not executed here. Clean Windows
installation, inference, cancellation, repeated requests and latency while
presenting remain release gates. Use a clean standard-user Windows account,
install the packaged Selah app, download Luma through its UI and run the same
English/Telugu/mixed/ambiguity examples before marking the gate complete.

## App-level results

All ten app-level scenarios passed on this Mac: English song routing through the
actual model; Telugu song commands; mixed-language song commands; misspelled
English references; Telugu John 3:16; mixed-language Genesis 1:1; missing-book,
multiple-book, missing-chapter and unavailable-verse clarification. The test
approved searches explicitly and compared exact installed Bible rows, while
asserting unchanged draft, program, catalog and live snapshot. The report records
`model`, `request` and `clarification` routes rather than attributing parser
successes to model accuracy.

The isolated in-app setup test downloaded all managed assets from the network,
verified their checksums and confirmed the assistant remained disabled. The
updates dialog reported the repository's no-published-stable-release state.

The final shared-download integration check also deliberately used a wrong
checksum and cancelled a subsequent HTTPS download. Both preserved an existing
destination, and reusing the downloader after failure worked. Windows runtime
inspection identified a valid PE x64 (`0x8664`) binary; this still is not a Windows
execution or clean-install result.
