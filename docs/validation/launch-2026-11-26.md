## Codec issue retained explicitly

The former 96×54 MPEG-4 Part 2 fixture produces a uniform green frame on this Qt/Mac
stack despite delivering frames. FFmpeg can extract the source pattern. H.264
renders correctly through the same standby path. Disabling hardware decode in a
follow-up run did not establish a fix. A minimal standalone Qt VideoOutput/MediaPlayer reproduces the green result without Selah or its transition shader. Qt logs list only the `darwin` backend on this installation; requesting FFmpeg cannot select a backend that is not installed. The fixture was replaced with H.264 for the
standard supported-content check; this does **not** fix or certify every MPEG-4 codec.
The strengthened smoke now fails on missing RGB test-pattern pixels, preventing a
false pass from decoder frame counts alone. Complete the advertised codec matrix
on final packages, and keep this legacy/tiny MPEG-4 case as a known issue until resolved
or explicitly excluded from supported codecs. No global decoding workaround was applied.

Reproduce:

```sh
ffmpeg -f lavfi -i testsrc=size=96x54:rate=8 -t 1 -c:v mpeg4 -q:v 6 -an tiny.mp4
build/Selah.app/Contents/MacOS/Selah --standby-smoke "$PWD/tiny.mp4" "$PWD/captures/tiny-mpeg4"
```
